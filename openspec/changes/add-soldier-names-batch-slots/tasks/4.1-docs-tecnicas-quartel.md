**06-api-rest.md:**
- Seção "Treino de unidades" (§9 ou equivalente):
  - Atualizar POST `/api/jogo/quartel/ordens`: novo corpo `TreinarRequest` com campos `tipo`, `armaNivel`, `armaduraModelo`, `armaduraNivel`, `quantidade`
  - Removido (não está mais no request): `armaId`, `armaduraId`
  - Resposta: `Ordem` criada com status TREINO
  - Validações: quantidade [1..15], itens suficientes, comida suficiente, capacidade
  - Erros: 400 (quantidade inválida), 422 (CAPACIDADE_EXERCITO, ITEM_INDISPONIVEL, RECURSOS_INSUFICIENTES)

- Seção "Consultar vila":
  - GET `/api/jogo/vila` retorna `VilaDto` com novo `UnidadeDto`: adicionar campos `nome`, `sobrenome`, `ordinalNome`, `nomeExibicao`, `equipamento`

  - Exemplo de resposta com unidade incluindo nome/sobrenome/equipamento

- Seção "Troca de equipamento" (novo endpoint):
  - POST `/api/jogo/unidades/{id}/equipamento` (corpo: {slot, itemId})
  - Resposta: `VilaDto` atualizada
  - Erros: 400 corpo inválido; 404 NAO_ENCONTRADO; 422 UNIDADE_EM_MASMORRA, ITEM_INDISPONIVEL

- Em "Códigos de Erro Específicos", acrescentar: novo `UNIDADE_EM_MASMORRA` (422)

- Nota sobre novo endpoint GET `/quartel/unidades/{id}`: rota SPA servida pelo backend (sem resposta JSON, retorna HTML)

**ADR 0024 (opcional):**
- Título: "Listas de nomes como recurso de classpath"
- Contexto: unidades anônimas → necessidade de nomes sorteados
- Decisão: usar `src/main/resources/jogo/nomes/` em vez de `docs/` (via pom `<resources>` + Dockerfile COPY)
- Razões: classpath padrão, sem configuração extra de build, arquivo único como fonte de verdade
- Consequências: JSONs carregados no boot do aplicativo, falha rápido se ausente/vazio, sem reload em runtime
