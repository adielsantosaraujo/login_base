**jogo.ts:**

Atualizar função de treino e adicionar função de troca:

```typescript
export interface TrocarEquipamentoRequest { slot: SlotEquipamento; itemId: number }

// Na prática, é um método do objeto jogoAPI:
export const jogoAPI = {
  async treinar(
    tipo: TipoTropa,
    armaNivel: number,
    armaduraModelo: ModeloItem,
    armaduraNivel: number,
    quantidade: number
  ): Promise<VilaDto> {
    const corpo: TreinarRequest = {
      tipo,
      armaNivel,
      armaduraModelo,
      armaduraNivel,
      quantidade,
    }
    return request('/api/jogo/quartel/ordens', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(corpo),
    })
  },
  
  async trocarEquipamento(unidadeId: number, slot: SlotEquipamento, itemId: number): Promise<VilaDto> {
    return request(`/api/jogo/unidades/${unidadeId}/equipamento`, {
      method: 'POST', headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ slot, itemId } satisfies TrocarEquipamentoRequest),
    })
  }
}
```

Observação para o redator: manter `status: StatusUnidade`, que já existe em `tipos.ts` (linha 32), no lugar de `string`.

## Critérios de aceite

- `TipoTropa`, `CategoriaItem`, `SlotEquipamento` como union types (não enums)
- `TreinarRequest` interface com campos corretos (armaNivel, armaduraModelo: ModeloItem, armaduraNivel, quantidade)
- `UnidadeDto` interface com nome, sobrenome, ordinalNome, nomeExibicao, equipamento (Record com 9 slots), `hp` único (não hpAtual/hpMaximo)
- `equipamento` é `Record<SlotEquipamento, ItemDto | null>` (slots vazios são null)
- `UnidadeDto` com `ordinalNome`/`nomeExibicao`; `jogoAPI.trocarEquipamento` envia POST com `{slot, itemId}` e retorna `Promise<VilaDto>`
- Função `jogoAPI.treinar` envia POST `/api/jogo/quartel/ordens` com novo contrato e retorna `Promise<VilaDto>`
