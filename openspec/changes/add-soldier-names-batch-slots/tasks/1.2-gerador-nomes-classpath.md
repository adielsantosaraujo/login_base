# Task 1.2 — JSONs movidos e gerador de nomes

**Índice:** [tasks.md](../tasks.md) · **Depende de:** — · **Paralela com:** 1.1, 1.3

## Objetivo

Mover os arquivos `nome_pessoas.json` e `sobrenome_pessoas.json` de `docs/` para `src/main/resources/jogo/nomes/`, criar o componente `GeradorNomes` que carrega as listas via classpath, configurar um bean separado `AleatorioNomes` para sorteios, e adicionar testes de geração de nomes.

## Contexto necessário

- [design.md — Decisão D1: Listas de nomes como recurso de classpath](../design.md#d1--listas-de-nomes-como-recurso-de-classpath) — por que mover para classpath
  > `git mv docs/nome_pessoas.json src/main/resources/jogo/nomes/`. Classpath padrão; Dockerfile já copia `src/`. Evita duplicação (docs + pom resources).

- [design.md — Decisão D2: GeradorNomes e bean separado AleatorioNomes](../design.md#d2--geradornomes-e-bean-separado-aleatorionomes) — arquitetura do gerador
  > Carrega as 2 listas via Jackson de `ClassPathResource("jogo/nomes/...")` no construtor; falha rápido se lista vazia/ausente; `NomePessoa sortear()` usa bean separado `AleatorioNomes` para não deslocar sequências determinísticas de loot/IA.

- [Aleatorio.java](/src/main/java/com/example/loginbase/jogo/config/Aleatorio.java) — interface ou classe base de randomização

- [AleatorioPadrao.java](/src/main/java/com/example/loginbase/jogo/config/AleatorioPadrao.java) — implementação padrão

- [AleatorioSequencia.java](/src/test/java/com/example/loginbase/jogo/suporte/AleatorioSequencia.java) — implementação de teste determinística

## Notas de implementação

**git mv (no shell do executor):**
```bash
git mv docs/nome_pessoas.json src/main/resources/jogo/nomes/nome_pessoas.json
git mv docs/sobrenome_pessoas.json src/main/resources/jogo/nomes/sobrenome_pessoas.json
```

**AleatorioNomes:**
- Criar classe `@Component` com método `int proximo(int limite)` que retorna índice aleatório
- Injetar `Aleatorio` (padrão) que implementa randomização verdadeira
- Nos testes, substituir por `AleatorioSequencia` (determinística) via `JogoTestConfig` se necessário

**GeradorNomes.java:**
- Localização: `src/main/java/com/example/loginbase/jogo/quartel/GeradorNomes.java`
- Anotação: `@Component`
- Construtor: carrega as 2 listas via `ClassPathResource` usando Jackson `ObjectMapper`
- Se lista vazia ou arquivo ausente: lançar `IllegalStateException` com mensagem clara (impede startup)
- Método público: `NomePessoa sortear()` → injeta `AleatorioNomes`, chama `aleatorio.proximoEntre(lista.size())`, retorna nome/sobrenome da lista

**AleatorioNomes.java:**
- Interface simples: `public interface AleatorioNomes { int proximoEntre(int tamanho); }`
- Ou classe: `public class AleatorioNomes` com injeção de `Aleatorio aleatorio` (padrão) ou `AleatorioSequencia` (testes)

**JogoConfig.java:**
- Registrar bean `AleatorioNomes` que wrappa ou qualifica a `Aleatorio` padrão
- Ou criar classe separada com `@Configuration` e `@Bean` para `AleatorioNomes`

**GeradorNomesTest.java:**
- Teste 1: `GeradorNomes` carrega listas sem erro; listas não vazias
- Teste 2: `sortear()` retorna nome de `nome_pessoas.json` e sobrenome de `sobrenome_pessoas.json`
- Teste 3: com `AleatorioSequencia`, validar que sorteios são determinísticos (ex.: 1º chama = primeiro nome, 2º chama = segundo nome)
- Teste 4: arquivo ausente causa `IllegalStateException` no construtor

## Critérios de aceite
