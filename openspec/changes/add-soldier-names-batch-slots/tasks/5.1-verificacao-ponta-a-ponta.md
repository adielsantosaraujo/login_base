## Notas de implementação

**1. Build Maven (backend + migrations):**
```bash
./mvnw clean install
```
- Executa todas as migrations (V1–V4)
- Compila código Java
- Executa todos os testes unitários e integração
- Gera arquivo WAR/JAR

**2. Build frontend (valida tipos TypeScript):**
```bash
cd frontend && npm run build
```
- Gera `frontend/dist/` com assets otimizados
- Sem erros Vite/Vue

**4. Teste manual — Treino em lote:**
- Iniciar aplicação: `./mvnw spring-boot:run` (ou deploy)
- Abrir frontend: navegar para `/quartel`
- Criar vila com Quartel N1
- Adicionar armas e armaduras ao inventário (via forja ou console DB)
- Executar treino: preencher tipo, nível arma, modelo/nível armadura, quantidade (ex.: 3)
- Verificar:
  - Ordem TREINO criada com `quantidade=3`
  - Comida debitada corretamente
  - Itens marcados `RESERVADO`
  - Progresso exibido: "Treinando 3 unidades"

**5. Teste manual — Conclusão e nomes:**
- Esperar conclusão de ordem (ou acelerar em DB: `UPDATE jogo_ordens SET conclui_em = now()`)
- Verificar:
  - 3 unidades criadas
  - Cada uma com nome + sobrenome; pares repetidos exibidos com sufixo
  - Itens marcados `EQUIPADO`
  - Ordem deletada

**5b. Teste manual — Nome repetido com sufixo:**
- Forçar repetição: no banco, `UPDATE jogo_unidades SET nome='Ana', sobrenome='Silva' WHERE id=<x>` não serve (não atualiza contador); em vez disso, treinar até repetir ou, em ambiente de teste, conferir `VilaServiceTest`/`NumeradorNomesTest` com `AleatorioSequencia` forçando o mesmo par em lote de 2
- Verificar: lista mostra "Ana Silva" e "Ana Silva (2)"; `SELECT * FROM jogo_contadores_nome` mostra `ultimo_ordinal = 2`
- Fazer "Ana Silva (2)" morrer e treinar nova "Ana Silva" (ou teste automatizado equivalente) → "Ana Silva (3)"

**6. Teste manual — Detalhe da unidade:**
- Na lista de unidades do Quartel, clicar no nome (ex.: "Ana Silva")
- Verificar:
  - Navega para `/quartel/unidades/{id}`
  - Exibe nome, tipo, status
  - Exibe 9 slots de equipamento em grid
  - Slots ARMA e ARMADURA preenchidos com modelo/nível
  - Slots 3–9 exibem "Vazio"
  - Botão "Voltar" retorna ao Quartel

**6b. Teste manual — Troca de equipamento:**
- Forjar uma Espada N2; no detalhe de um Soldado `DISPONIVEL`, clicar "Trocar" no slot Arma e escolher a Espada N2
- Verificar: slot Arma mostra Espada N2, ataque atualizado; Espada N1 voltou a `DISPONIVEL` (Forja/inventário)
- Diálogo não lista Arco/Lança para Soldado; lista couro e ferro para Armadura
- Enviar unidade a uma masmorra → no detalhe, "Trocar" desabilitado; POST manual retorna 422 `UNIDADE_EM_MASMORRA`
- Unidade que trocou de arma morre → Espada N2 e armadura apagadas; Espada N1 continua `DISPONIVEL`

**7. Teste manual — Erros:**
- Tentar treinar com quantidade > máximo → erro 422 exibido
- Tentar treinar sem armas suficientes → erro 422 exibido
- Tentar treinar com quantidade 0 ou 16 → erro 400 exibido

**8. Teste manual — Morte:**
- Ir a Masmorras
- Unidade morre em combate
- Verificar: unidade deletada, itens (arma + armadura) deletados

## Critérios de aceite

- `./mvnw clean install` passa sem erro (todos os testes)
- `cd frontend && npm run build` gera `frontend/dist/` sem erro
- Teste manual de treino em lote: 3 unidades criadas com nomes
- Nome repetido exibido com sufixo "(N)", contagem incluindo mortas
- Teste manual de detalhe: 9 slots exibidos, 2 preenchidos, 7 vazios
- Troca de Arma/Armadura funciona, item retirado volta ao inventário, bloqueio em masmorra retorna 422 `UNIDADE_EM_MASMORRA`
- Teste manual de erros: 422 e 400 retornados corretamente
- Teste manual de morte: itens destruídos
- Banco de dados em estado consistente (sem dados órfãos)
