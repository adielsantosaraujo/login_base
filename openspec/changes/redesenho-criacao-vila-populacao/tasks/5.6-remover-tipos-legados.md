## Objetivo

Remover os tipos de região legados `RURAL` e `COLETA` do enum `TipoRegiao`, limpar referências nos testes e validar que toda a suíte de testes backend passa (verde).

## Contexto necessário

- [design.md — D1. Tipos e bônus de região](../design.md#d1-tipos-e-bônus-de-região) — os 5 tipos v2 são FLORESTA, PLANICIE, URBANA, LITORAL, MONTANHA; RURAL e COLETA são legados
- [design.md — D6. Schema V17 sem retrocompatibilidade](../design.md#d6-schema-v17-sem-retrocompatibilidade) — o banco só aceita os 5 tipos v2
- [/src/main/java/com/example/loginbase/jogo/modelo/TipoRegiao.java](/src/main/java/com/example/loginbase/jogo/modelo/TipoRegiao.java) — Enum com RURAL e COLETA (remover)
- Arquivos que referenciam tipos legados (resultado de `grep -rn "TipoRegiao.RURAL\|TipoRegiao.COLETA\|\"RURAL\"\|\"COLETA\"" src`)

## Arquivos a criar/alterar

- [/src/main/java/com/example/loginbase/jogo/modelo/TipoRegiao.java](/src/main/java/com/example/loginbase/jogo/modelo/TipoRegiao.java) (remover RURAL e COLETA legados, manter os 5 tipos v2)
- Todos os arquivos de teste que usam tipos legados (rodar o grep da seção Contexto; hoje ele aponta, em src/test: CasamentoIntegrationTest, PopulacaoControllerIntegrationTest, ConstrucaoCatalogoTest, ConstrucaoServiceIntegrationTest, MarcacaoIntegrationTest, MapaControladorIntegrationTest, RegiaoControladorIntegrationTest, VilaControladorIntegrationTest, ProducaoFabricasIntegrationTest, ProducaoServiceIntegrationTest, ModeloJogoBaseIntegrationTest — a maioria já corrigida pelas tasks 3.x/5.x)

## Notas de implementação

```java
// Antes (durante a change): FLORESTA, PLANICIE, URBANA, LITORAL, MONTANHA, @Deprecated RURAL, @Deprecated COLETA
// Depois:
public enum TipoRegiao { FLORESTA, PLANICIE, URBANA, LITORAL, MONTANHA; /* nomeExibicao, bonus(), atuais() mantidos */ }
```

- Substituir `TipoRegiao.COLETA` por um tipo v2 coerente com o prédio do teste (ex.: `MONTANHA` para mina/pedreira, `FLORESTA` para lenhadores)
- Substituir `TipoRegiao.RURAL` por `PLANICIE` (fazendas) ou outro tipo v2 coerente

**Observação importante:**

- `ProducaoService.CATEGORIA_RURAL` e `ProducaoService.CATEGORIA_COLETA` são **categorias de prédio**, não tipos de região — **NÃO alterar**
- `CatalogoPrediosProducao.ehRural` é método de prédio — **NÃO alterar**

## Critérios de aceite

- Enum `TipoRegiao` sem RURAL nem COLETA legados
- Grep de `"RURAL"|"COLETA"` não encontra usos de tipo de região em src (apenas categorias de prédio e métodos)
- `./mvnw verify` verde (testes de unitário, integração, build)
- Banco de teste `login_base_t56` recriado antes do `verify` (PostgreSQL)

## Verificação

```bash
cd /mnt/d/desenvolvimento/projetos/login_base
grep -rn 'TipoRegiao\.\(RURAL\|COLETA\)\|"RURAL"\|"COLETA"' src --include="*.java" | grep -v "CATEGORIA_"
docker compose exec -T db dropdb -U login_base --if-exists login_base_t56
docker compose exec -T db createdb -U login_base login_base_t56
JAVA_HOME=/usr/lib/jvm/jdk-25.0.2-oracle-x64 DB_NAME=login_base_t56 ./mvnw verify
```

O grep só pode listar as constantes de categoria de prédio (`CATEGORIA_RURAL`/`CATEGORIA_COLETA`) e as strings de categoria. Proibido `git stash`/`git checkout`.

## Fora de escopo

- Remover categorias de prédio (CATEGORIA_RURAL, CATEGORIA_COLETA) — são de modelo de prédio, não de tipo de região
- Remover método `ehRural` de `CatalogoPrediosProducao` — é método de prédio
- Tipos de região em specs e documentação (fora do código Java)
