## Notas de implementação

- **VilaPreviaService:** `@Service` com `VilaPreviaRepository`, `VilaRepository` e `GeradorMapaService` injetados pelo construtor. Método `PreviaMapaDTO gerar(Long usuarioId)` (cria nova ou renova; ThreadLocalRandom para semente; incrementa rodada). Método `PreviaMapaDTO obter(Long usuarioId)` (404 PREVIA_NAO_ENCONTRADA se não existe). Método `void exigirVigente(Long usuarioId, UUID previaId)` (lança PreviaExpiradaException se mismatch). `gerar` e `obter` lançam `VilaJaExisteException` (409 `VILA_JA_EXISTE`) se o usuário já tem vila. Método `void remover(Long usuarioId)` (usado na task 3.2). Primeira prévia: `rodada = 1`; as seguintes trocam `semente` e `previaId` e fazem `rodada + 1`. O mapa é **regenerado** da semente a cada GET (não é gravado).

- **PreviaMapaDTO:** `UUID previaId, int rodada, List<RegiaoPreviaDTO> regioes` (sempre 16).
- **RegiaoPreviaDTO:** `int indice, TipoRegiao tipo, List<RegiaoBonusDTO> bonus`.
- **RegiaoBonusDTO:** `BonusRegiao bonus, int posicao, int valor`.

- **Exceções:** PreviaNaoEncontradaException (404 PREVIA_NAO_ENCONTRADA, mensagem "Nenhuma prévia de mapa gerada"), PreviaExpiradaException (409 PREVIA_EXPIRADA). Ambas estendem `JogoException` e usam `CodigoErro` (task 2.3).

- **VilaControlador:** `@PostMapping("/previa")` (200, devolve `PreviaMapaDTO`), `@GetMapping("/previa")` (200 `PreviaMapaDTO`). Ambos usam `UsuarioAtual`.

- **VilaPreviaIntegrationTest:** testes dos cenários (rodada 1→2→3 com previaId diferente; GET idêntico; 404; 409 com vila; 16 regiões; 3 bônus; faixas válidas; 401 sem autenticação).

## Critérios de aceite

- Cenários do spec cobertos por testes.
- 16 regiões, 3 bônus, faixas válidas.
- Usuário sem prévia ⇒ GET 404 `PREVIA_NAO_ENCONTRADA`.
- Usuário com vila ⇒ POST e GET 409 `VILA_JA_EXISTE`.
- GET repetido ⇒ JSON idêntico.
