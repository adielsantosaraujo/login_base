## Notas de implementação

- **JogoException:** adicionar `String codigo` (getter); construtor novo `JogoException(HttpStatus status, String codigo, String mensagem)`; construtor atual continua (codigo nulo).

- **CodigoErro:** classe final com 15 constantes `public static final String` (VILA_JA_EXISTE, PREVIA_NAO_ENCONTRADA, PREVIA_EXPIRADA, SELECAO_INVALIDA, REGIAO_NAO_ADJACENTE, SEM_REGIAO_URBANA, VILA_NAO_ENCONTRADA, POPULACAO_JA_CONFIRMADA, POPULACAO_INCOMPLETA, PONTOS_INVALIDOS, LIMITE_CARACTERISTICAS, LIMITE_PROFISSOES, FAMILIA_LIDER_OBRIGATORIA, MINIMO_CONSTRUTORES, MINIMO_CARREGADORES).

- **ApiExceptionHandler:** corpo com `LinkedHashMap` em ordem (erro primeiro, codigo segundo); `codigo` presente só se não null; `MethodArgumentNotValidException` continua só com erro.

- **Exceções existentes:** `VilaJaExisteException` → `super(HttpStatus.CONFLICT, CodigoErro.VILA_JA_EXISTE, "Usuário já possui uma vila")`; `RegiaoNaoAdjacenteException` → 400 `REGIAO_NAO_ADJACENTE`; `UrbanaObrigatoriaException` → 400 `SEM_REGIAO_URBANA`; `VilaNaoEncontradaException` → 404 `VILA_NAO_ENCONTRADA` (mantém a mensagem atual).

- **Mensagem de UrbanaObrigatoriaException:** "Ao menos uma região deve ser Urbana".

## Critérios de aceite

- Exceção com código ⇒ JSON `{erro, codigo}`.
- Exceção sem código ⇒ JSON com só `erro`.
- Status HTTP preservado.
- Testes passam com novos códigos.
