## Notas de implementação

- Estado reativo:
  - `previa` (dados da prévia com regiões, rodada, ID)
  - `selecionadas` (array de índices na ordem de clique)
  - `hover` (índice sob mouse ou foco)
  - `gerando` (carregando nova prévia)
  - `enviando` (enviando POST de criação)
  - `erro` (mensagem de erro da API)

- Funções:
  - `carregarPrevia()` → GET `/api/jogo/vila/previa` (POST se 404)
  - `alternar(indice)` → toggle seleção
  - `gerar()` → POST nova prévia, limpa `selecionadas`
  - `criar()` → POST `/api/jogo/vila` com `{previaId, indices: selecionadas}`, após sucesso chama `marcarVilaCriada()` e push `/jogo/distribuir-populacao`
  - `setHover(indice)` → `hover = indice`
  - `limparHover()` → `hover = null`

- Derivados usam `regioes.ts`:
  - `podeSelecionar(indice)` → usando `regioes.podeSelecionar(selecionadas, indice)`
  - `conectado()` → usando `regioes.conectado(selecionadas)`
  - `totaisBonus()` → usando `regioes.totaisBonus(selecionadas, previa.regioes)`
  - `dicaSelecao()` → usando `regioes.dicaSelecao(...)`

- Erros:
  - `PREVIA_EXPIRADA` (409) → `erro` com a mensagem do backend, recarrega a prévia com GET e limpa `selecionadas`
  - `VILA_JA_EXISTE` → `resetarGuardaVila()` + `router.push('/jogo/mapa')`
  - Outros erros → mostrar mensagem
- `limparHover()` volta o foco do card para a última selecionada (o card 'Em foco' usa `hover ?? última selecionada`).

## Critérios de aceite

- GET 404 ⇒ POST nova prévia
- `gerar()` limpa seleção
- Criar com sucesso ⇒ `marcarVilaCriada()` + push
- `PREVIA_EXPIRADA` ⇒ recarregar e limpar
- `VILA_JA_EXISTE` ⇒ reset + push `/jogo/mapa`
- Testes cobrindo todos os cenários
