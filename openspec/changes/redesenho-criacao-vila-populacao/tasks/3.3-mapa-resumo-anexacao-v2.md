## Notas de implementação

- **DTOs:** adicionar campo `List<RegiaoBonusDTO> bonus` a regiões (indice, tipo, 3 bônus). `VilaResumoDTO` e `MapaDTO` ganham `Map<BonusRegiao,Integer> bonusRegiao` da vila (13 chaves).

- **RegiaoDetalheDTO:** tipo (novo), 3 bônus (novo), ladrilhos (persistidos ou gerados se tipo ≠ URBANA).

- **Anexação:** corpo vazio (POST sem `AnexarRegiaoRequest`); tipo/bônus vêm do `regiao.tipo` gravado na criação. Se região não tiver tipo (só testes antigos), erro 400 "Região sem tipo".

- **Ladrilhos:** em `RegiaoDetalheDTO.ladrilhos`: se persistidos, retorna; se não e tipo ≠ URBANA, gera com `GeradorJazidaService`.

- **Testes:** ajustar setups que usavam `{tipo:"COLETA"}` para usar tipos v2 (ex.: MONTANHA) com tipo gravado.

- `bonusRegiao` vem de `BonusRegiaoService.bonusDaVila(vilaId)` (13 chaves, ordem do enum).

- Anexação: gerar os ladrilhos se ausentes para **qualquer** tipo (hoje `AnexacaoService` linha ~116 só gera para COLETA). No detalhe (`MapaService` linha ~95), gerar para exibição se ausentes e tipo ≠ URBANA.

- Custos, adjacência e masmorra da anexação não mudam.

## Critérios de aceite

- Cenários do spec cobertos por testes.
- `bonusRegiao` com 13 chaves (sempre); região não possuída mostra tipo/bônus da criação.
- Anexar sem corpo mantém tipo/bônus; soma ao `bonusRegiao`.
- Ladrilhos gerados para tipo ≠ Urbana.
