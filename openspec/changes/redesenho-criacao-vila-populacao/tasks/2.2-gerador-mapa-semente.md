## Notas de implementação

- **GeradorMapaService:** classe com `@Service` puro (sem `@Autowired`, sem banco). Método `List<RegiaoGerada> gerar(long semente)`. Records aninhados: `record RegiaoGerada(int indice, TipoRegiao tipo, List<BonusGerado> bonus)`, `record BonusGerado(BonusRegiao bonus, int posicao, int valor)` (lista ordenada por posição 1–3).

- Algoritmo (cópia fiel do JS): `inteiro(min, max) = min + rng.nextInt(max - min + 1)`, embaralhar Fisher–Yates (for i = n-1..1: j = inteiro(0, i); troca), `sortearQuantidades` com amostragem por rejeição (5 inteiros 2..4 na ordem dos tipos, aceita se soma 16 e ≤2 com 4), layout embaralhado, para cada região (índice 1..16): embaralha bônus do tipo, sorteia valor de cada posição pela faixa.

- Métodos auxiliares: `boolean conectadas(List<Integer> indices)` com BFS ortogonal; `Map<BonusRegiao,Integer> somarBonus(List<RegiaoGerada> mapa, Collection<Integer> indices)` com EnumMap (13 chaves, 0 quando ausente).

- **GeradorMapaServiceTest:** testes unitários (sem banco, sem Spring). Sementes 0..999:
  - R8: cada tipo em 2–4 regiões.
  - R9: soma 16.
  - R10: máx 2 tipos com 4.
  - R11: 16 índices 1..16.
  - R13: 3 bônus distintos do tipo.
  - R14/R15: faixa por posição, incluindo limites alcançáveis (35, 50, 16, 34, 5, 15).
  - R16: todo bônus em todas as posições ao longo das sementes.
  - Ambas as famílias de distribuição (4,4,3,3,2 e 4,3,3,3,3) aparecem.
  - Determinismo: mesma semente ⇒ mapa idêntico.
  - Sempre existe ao menos uma seleção válida (2–4 Urbanas).
  - `conectadas([1,3,2])` true, `[1,3,6]` false.
  - `somarBonus` reproduz Exemplo 2 (mapa montado à mão no teste).

## Critérios de aceite

- Para sementes 0..999: todas as regras R8–R16 cobertas.
- Determinismo: `gerar(42)` dá o mesmo resultado duas vezes.
- Conectividade: BFS com ortogonal.
- Soma de bônus: EnumMap com 13 chaves.
