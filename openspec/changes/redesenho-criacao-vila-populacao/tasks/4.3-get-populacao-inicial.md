## Objetivo

Implementar o novo contrato do `GET /api/jogo/vila/populacao` que devolve a população inicial calculada com ordenação determinística e sugestão de líder de família.

  > Família líder por id: GET devolve `familiaLiderSugeridaId` (e `familiaLiderId`, nulo até confirmar). Chaves de característica em MAIÚSCULAS (VIT, FOR, VEL, INT, CAR); `profissoes` sempre com as 12 chaves (zeros incluídos).

## Notas de implementação

**PopulacaoDTO — estrutura nova:**

```java
record PopulacaoDTO(boolean populacaoConfirmada, Map<Profissao,Integer> plano, Map<Profissao,Integer> minimos,
                    LimitesDTO limites, Long familiaLiderSugeridaId, Long familiaLiderId, List<FamiliaDTO> familias) { }
record LimitesDTO(int caracteristicasTotal, int profissoesTotal) { }   // 20 e 10
record FamiliaDTO(Long familiaId, String sobrenome, List<CidadaoDTO> cidadaos) { }
record CidadaoDTO(Long cidadaoId, String nome, Sexo sexo, int idadeAnos, PapelFamiliar papel,
                  LinkedHashMap<Caracteristica,Integer> caracteristicas, LinkedHashMap<Profissao,Integer> profissoes) { }
```

- `plano` em LinkedHashMap na ORDEM_PLANO; `minimos` = {CONSTRUTOR: 2, CARREGADOR: 2}; `limites` = {20, 10}.
- `familiaLiderSugeridaId` = id da família no índice devolvido por `DistribuicaoPopulacao.familiaLiderSugerida` (líder = adulto mais velho; maior CAR; empate → primeira), calculado sobre os pontos exibidos (sugestão ou gravados).
- `PopulacaoService.obter(usuarioId)`: carrega a vila do usuário (404 se não houver), famílias por id, cidadãos vivos por família na ordem PAI, MAE, FILHO, FILHA; se pendente, monta a sugestão com `distribuirPopulacao(familias, PLANO_PADRAO)`; se confirmada, lê `cidadao` e `cidadao_profissao`.
- Remover o contrato antigo do GET (pontos incrementais) do `PopulacaoDTO`.

## Critérios de aceite
- Vila recém-criada: `populacaoConfirmada` false, 16 cidadãos com a sugestão do plano padrão; o pai da 1ª família é Comerciante com CAR 13 (o nome é o gerado, não "Marcos"); `familiaLiderSugeridaId` = id da 1ª família.
- Duas consultas seguidas devolvem JSON idêntico.
- `profissoes` com 12 chaves; `caracteristicas` com 5 chaves em MAIÚSCULAS.
- Após confirmar (montado via repositório no teste), devolve os valores gravados e `familiaLiderId`.
- Usuário sem vila ⇒ 404 `VILA_NAO_ENCONTRADA`.
