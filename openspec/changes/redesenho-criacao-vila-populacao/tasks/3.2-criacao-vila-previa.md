## Notas de implementação

- **VilaService.criarVila:** método público. Validações em ordem: 1. vila existente (409 VILA_JA_EXISTE), 2. prévia vigente (409 PREVIA_EXPIRADA via `exigirVigente`), 3. índices válidos (400 SELECAO_INVALIDA), 4. conexo (400 REGIAO_NAO_ADJACENTE), 5. Urbana (400 SEM_REGIAO_URBANA). Substituir o atual `criarVila(usuarioId, indices, tipos, semente)` por `criarVila(Long usuarioId, UUID previaId, List<Integer> indices)` (API) e criar `criarVilaComSemente(Long usuarioId, long semente, List<Integer> indices)` (usado por `criarVila` e pelos testes).

- Efeitos: gera mapa de `GeradorMapaService.gerar(semente)`, grava 16 regiões com tipo e 3 `RegiaoBonus` cada, marca 3 como possuídas, cria estoque inicial, 4 casas N1 em x=0,2,4,6 / y=0 da 1ª Urbana de `indices`, 16 cidadãos com 0 pontos (via `FamiliaService.gerarFamiliasIniciais`), apaga prévia.

- **MapaTestes:** classe utilitária (pode ficar em test package) com método `static List<Integer> selecioneValidas(List<RegiaoGerada> mapa, boolean comUrbana)` que retorna 3 índices conexos (com/sem Urbana).

- **Testes:** cenários do spec (validação em ordem, casas em posição correta, 16 cidadãos, prévia apagada, segunda criação ⇒ 409).

- `SelecaoInvalidaException` → 400 `SELECAO_INVALIDA` com a mensagem "Escolha 3 regiões diferentes de 01 a 16" (indices nulo, ≠ 3 itens, repetidos ou fora de 1..16).

- Prévia: `VilaPreviaService.exigirVigente(usuarioId, previaId)` (409 `PREVIA_EXPIRADA` se não há prévia, se `previaId` é nulo ou se é diferente da vigente); apagar com `VilaPreviaService.remover(usuarioId)` na mesma transação.

- Conectividade: `GeradorMapaService.conectadas(indices)` (BFS ortogonal; `[1,3,2]` é aceito, `[1,3,6]` não).

- Ladrilhos: gerar com `GeradorJazidaService` só para as 3 regiões possuídas (como hoje). `vila.semente` = semente da prévia.

- O controlador responde 201 com `{ "vilaId": <id>, "proximaEtapa": "DISTRIBUIR_POPULACAO" }`.

- `PopulacaoControllerIntegrationTest`: trocar só a criação da vila do setup (POST `/previa` + POST `/vila`). As asserções de população são reescritas nas tasks 4.3/4.4; falhas nelas são esperadas aqui (essa classe não está na verificação).

## Critérios de aceite

- 16 cidadãos com 0 pontos.
