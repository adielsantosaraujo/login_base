# Task 4.2 — Serviço da fazenda

**Índice:** [tasks.md](../tasks.md) · **Depende de:** 3.2 · **Paralela com:** 4.1, 4.3, 4.4, 5.3, 6.1

## Objetivo
Criar o `FazendaService` que gerencia plantio em canteiros. O plantio é **instantâneo**: escolhe um canteiro, consome 1 semente (ou nenhuma para TRIGO), substitui o cultivo e começa a produzir imediatamente.

## Notas de implementação

**FazendaService** (`@Service`, `@Transactional`):
- `plantar(long usuarioId, int posicao, Cultivo cultivo): void`
  - Obtém vila com lock: `vila = vilaService.obterParaAtualizacao(usuarioId)`
  - Valida:
    1. `posicao > fazenda.nivel` → `CANTEIRO_INEXISTENTE`
    2. `cultivo ≠ TRIGO` e estoque de semente = 0 → `SEMENTE_INDISPONIVEL`
  - Se `cultivo ≠ TRIGO`: decrementa estoque de semente (+1)
  - Busca ou cria Canteiro na posição; substitui cultivo; atualiza `plantado_em = now`
  - Salva canteiro
  - Efeito **instantâneo**: próximas sincronizações já contam a nova produção

**Testes** (`@DataJpaTest`, `@Import`):
- Plantio de TRIGO (sem semente consumida)
- Plantio de MILHO com semente disponível (decrementa estoque)
- Erro CANTEIRO_INEXISTENTE (posição > fazenda.nivel)
- Erro SEMENTE_INDISPONIVEL (cultivo ≠ TRIGO e sem semente)
- Produção: após plantio, taxa de comida/h atualiza
- Troca de cultivo: TRIGO→MILHO; produção anterior (TRIGO até agora) é contada, depois MILHO começa a render

## Critérios de aceite
- Plantio é instantâneo (sem ordem)
- TRIGO não consome semente
- Outros cultivos consomem 1 semente
- Canteiro inexistente retorna 422 `CANTEIRO_INEXISTENTE`
- Sem semente retorna 422 `SEMENTE_INDISPONIVEL`
- Produção de comida/h reflete o novo cultivo imediatamente
- Troca de cultivo conta a produção anterior até o instante
