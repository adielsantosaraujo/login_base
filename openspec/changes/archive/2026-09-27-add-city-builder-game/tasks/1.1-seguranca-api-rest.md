# Task 1.1 — Segurança da API REST

**Índice:** [tasks.md](../tasks.md) · **Depende de:** — · **Paralela com:** 1.2, 1.3, 1.4, 7.1

## Objetivo
Estender o `SecurityConfig` para que requisições anônimas a endpoints `/api/**` retornem HTTP **401 sem redirecionamento**, e que o request cache não salve essas requisições para pós-login. Demais rotas continuam redirecionando para `/login`.

## Contexto necessário
- [SecurityConfig.java](/src/main/java/com/example/loginbase/seguranca/SecurityConfig.java) — existente, com rotas públicas e form login
- [user-authentication — spec](../specs/user-authentication/spec.md#requirement-proteção-de-rotas) — WHEN anônimo `GET /api/jogo/vila` → THEN 401; após login → `/`
- [user-authentication — spec](../specs/user-authentication/spec.md#requirement-proteção-csrf-para-clientes-javascript) — token em cookie `XSRF-TOKEN` via `csrf.spa()`, cabeçalho `X-XSRF-TOKEN`

## Arquivos a criar/alterar
- [SecurityConfig.java](/src/main/java/com/example/loginbase/seguranca/SecurityConfig.java)
- [ApiSegurancaWebMvcTest.java](/src/test/java/com/example/loginbase/web/ApiSegurancaWebMvcTest.java) (novo)

## Notas de implementação
- `exceptionHandling.defaultAuthenticationEntryPointFor(new HttpStatusEntryPoint(UNAUTHORIZED), PathPatternRequestMatcher.withDefaults().matcher("/api/**"))` — 401 sem redirecionamento apenas para `/api/**`
- `requestCache`: criar `HttpSessionRequestCache` customizado que **não salva** requisições a `/api/**`
- `csrf(csrf -> csrf.spa())` — token em cookie `XSRF-TOKEN` (não HttpOnly), aceito no cabeçalho `X-XSRF-TOKEN`
- Formulário Thymeleaf de login continua com parâmetro `_csrf`
- Testes: controller de teste aninhado `/api/teste`, verificar 401 anônimo, 200 com CSRF, CSRF faltante → 403

## Critérios de aceite
- GET `/api/**` anônimo recebe 401 sem redirecionamento para `/login`
- POST `/api/**` autenticado sem token `X-XSRF-TOKEN` recebe 403
- POST `/api/**` autenticado com token válido recebe 200
- Rotas não-API (ex. `/`) continuam redirecionando anônimo para `/login`
- Login após requisição a `/api/**` não redireciona para JSON (request cache ignorado)
- Formulário `/login` ainda funciona (parâmetro `_csrf` lido do HTML)

## Verificação
```bash
./mvnw test -Dtest='ApiSegurancaWebMvcTest,AutenticacaoWebMvcTest'
```
Testes antigos (`AutenticacaoWebMvcTest`) continuam passando; `ApiSegurancaWebMvcTest` novo passa (401, 403, 200, request cache).

- Proteção de rotas específicas por permissão (apenas autenticação)
- Tarefas paralelas 1.2, 1.3, 1.4 (outras camadas da stack)
