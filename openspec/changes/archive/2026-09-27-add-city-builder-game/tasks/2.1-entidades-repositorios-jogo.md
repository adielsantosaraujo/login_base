## Notas de implementação

**Entidades** (todas estendem `EntidadeAuditavel`):

1. **Vila**: `usuario_id` (FK), `nome`, `comida/madeira/pedra/ferro` (bigint milésimos), `recursos_atualizados_em`, `masmorra_nivel_liberado` (default 1)
   - Relação 1:N com Predio, Canteiro, EstoqueSemente, Item, Unidade, Ordem, Batalha

2. **Predio**: `vila_id` (FK), `tipo` (enum TipoPredio via VARCHAR), `nivel` (0–5)
   - PK composta? Ou `unique(vila_id, tipo)`

3. **Canteiro**: `vila_id` (FK), `posicao` (1–5), `cultivo` (enum Cultivo), `plantado_em`
   - `unique(vila_id, posicao)`

4. **EstoqueSemente**: `vila_id` (FK), `cultivo` (enum), `quantidade` (≥0)
   - `unique(vila_id, cultivo)`

5. **Item**: `vila_id` (FK), `modelo` (enum ModeloItem), `nivel` (1–5), `origem` (enum OrigemItem: FORJA, MASMORRA), `status` (enum StatusItem: DISPONIVEL, RESERVADO, EQUIPADO)

6. **Unidade**: `vila_id` (FK), `tipo` (enum TipoTropa), `arma_item_id` (FK Item), `armadura_item_id` (FK Item), `status` (enum StatusUnidade: DISPONIVEL, EM_MASMORRA)

7. **Ordem**: `vila_id` (FK), `categoria` (enum CategoriaOrdem: CONSTRUCAO, FORJA, TREINO), `alvo` (VARCHAR tipo/modelo), `nivel` (nullable), `quantidade` (default 1), `arma_item_id`, `armadura_item_id`, `iniciada_em`, `conclui_em`
   - `unique(vila_id, categoria)` — fila de 1 por categoria

8. **Batalha**: `vila_id` (FK), `masmorra_nivel`, `status` (enum StatusBatalha: EM_ANDAMENTO, VITORIA, DERROTA), `turno`, `estado` (JSON via conversor), `log` (text), `loot` (JSON nullable), `iniciada_em`, `finalizada_em` (nullable), `version` (otimistic lock)
   - Índice único parcial: `(vila_id) where status = 'EM_ANDAMENTO'`

**Repositórios**:
- `VilaRepository`: `findByUsuarioIdParaAtualizacao(Long usuarioId)` com `@Lock(PESSIMISTIC_WRITE)`
- Demais: métodos CRUD padrão (Spring Data cria automaticamente)

**Conversor JSON**:
- `@Converter(autoApply = true)` — Jackson `ObjectMapper` para serializar/desserializar `EstadoBatalha` e `Loot` em `estado` e `loot`

## Critérios de aceite
- 8 entidades mapeadas corretamente para as colunas de V3
- Enums salvos como VARCHAR via `@Enumerated(EnumType.STRING)`
- FKs funcionando (cascata apropriada ou não)
- Auditoria herdada de `EntidadeAuditavel` e aplicada
- `VilaRepository.findByUsuarioIdParaAtualizacao` com lock pessimista compilado
- Testes `@DataJpaTest`: criar vila, associar prédios/canteiros/itens, unique constraints funcionam
- Índices criados (verificável em `psql`)

## Verificação
```bash
make up
./mvnw test -Dtest=LoginBaseApplicationTests
./mvnw test -Dtest=RepositoriosJogoTest
```

`LoginBaseApplicationTests` valida o schema; `RepositoriosJogoTest` testa grava/lê entidades e constraints (replace NONE, rollback por teste).
