## Notas de implementação

### Conteúdo da seção

#### Cabeçalho e acesso
- Como abrir o jogo: `http://localhost:5173` após `make up` e backend rodando.
- Necessário: autenticação (usar credenciais de usuário cadastrado).

#### Configuração de variáveis
- `BACKEND_URL`: padrão `http://localhost:8080`; na change alterar para `http://app:8080` em ambiente local (Docker).
- `JOGO_VELOCIDADE`: padrão 1 (tempo real); aumentar para testar (ex.: 60 = tudo 60× mais rápido).

#### Estrutura do jogo
- Breve narrativa: o jogador controla uma vila com prédios, cultivos, tropas e enfrenta masmorras.
- **Recursos**: comida, madeira, pedra, ferro (produzidos/armazenados com limite).
- **Prédios**: centro da vila (limita outros), armazém (capacidade), fazenda, serraria, pedreira, mina de ferro, forja, quartel.
- **Canteiros**: plantam cultivos (TRIGO/MILHO/BATATA/ABOBORA_DOURADA) que produzem comida.
- **Forja**: cria armas e armaduras com custos em recursos.
- **Quartel**: treina tropas (SOLDADO/ARQUEIRO/LANCEIRO) que requerem arma e armadura.
- **Masmorras**: 5 níveis com inimigos; vitória libera próximo nível; derrota é reversível.

#### Fluxo de jogo típico
1. Login via form Thymeleaf.
2. Vila criada automaticamente no primeiro acesso.
3. Construir prédios para aumentar capacidade.
4. Forjar armas/armaduras.
5. Treinar tropas.
6. Entrar em masmorra com até 4 unidades.
7. Combate tático em turno (mover, atacar, defender).
8. Vitória = loot (recursos, sementes, itens) + nível liberado.

#### Endpoints da API
Tabela com método, rota e breve descrição:
- `GET /api/jogo/catalogo` — tabelas de custos, cultivos, tropas, inimigos, masmorras.
- `GET /api/jogo/vila` — estado atual (recursos, prédios, ordens, canteiros, itens, unidades, batalha ativa).
- `POST /api/jogo/predios/{tipo}/melhorar` — melhora um prédio.
- `POST /api/jogo/canteiros/{posicao}/plantar` — planta cultivo em canteiro.
- `POST /api/jogo/forja/ordens` — cria ordem de forja.
- `POST /api/jogo/quartel/ordens` — cria ordem de treino.
- `POST /api/jogo/masmorras/{nivel}/batalhas` — inicia batalha no nível.
- `GET /api/jogo/batalhas/{id}` — consulta batalha.
- `POST /api/jogo/batalhas/{id}/acoes` — executa ação de combate.

#### Autenticação e CSRF
- Login via form POST `/login` (e-mail + senha).
- Sessão HTTP via cookie `JSESSIONID`.
- API: POST exigem token CSRF em header `X-XSRF-TOKEN` (lido de cookie `XSRF-TOKEN`).
- Anônimo a `/api/**` recebe 401 e é redirecionado a `/login`.

#### Exemplo de uso (CLI + cURL)
- Comando: `make up` para subir containers.
- Login: `curl -b cookies.txt -c cookies.txt -d 'login=user@example.com&senha=senha' http://localhost:8080/login`.
- Consultar vila: `curl -b cookies.txt http://localhost:8080/api/jogo/vila`.

#### Notas de desenvolvimento

- Schema do banco em `src/main/resources/db/migration/V3__jogo.sql`.
- Testes de serviço em `src/test/java/.../jogo/**Test.java` (exigem `make up`).
