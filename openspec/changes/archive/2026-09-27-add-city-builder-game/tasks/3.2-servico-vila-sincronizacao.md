## Notas de implementação

**VilaService** (`@Service`, `@Transactional`):
- `obterParaAtualizacao(long usuarioId): Vila`
  - Tenta `VilaRepository.findByUsuarioIdParaAtualizacao(usuarioId)`
  - Se não existe: em caso de `DataIntegrityViolationException`, cria novo em transação `REQUIRES_NEW`, depois relê
  - Transação com lock pessimista
  - Retorna vila após `sincronizar()`

- `sincronizar(vila, agora: Instant): void` — chamado em todo obterParaAtualizacao e em todo comando
  - Busca ordens com `conclui_em <= agora`, ordena por `(concluiEm, id)`
  - Para cada ordem vencida:
    - `produzirAte(vila, ordem.concluiEm)` — atualiza recursos/data
    - `aplicador.aplicar(ordem)` — aplica efeito (sobe nível, cria itens, cria unidade)
    - Deleta ordem do repo
  - `produzirAte(vila, agora)` — atualiza recursos até agora
  - Persiste vila

- `consultar(long usuarioId): EstadoVila` — read-only snapshot para mapper
  - Chama `obterParaAtualizacao`, monta snapshot com dados atualizados
  - Útil para DTOs

- `produzirAte(vila, dataAlvo: Instant): void` — privado, atualiza `vila.recursos` e `recursos_atualizados_em`
  - Usa `CalculadoraProducao` com velocidade injetada
  - `dtMs = dataAlvo − vila.recursos_atualizados_em`
  - Se dtMs ≤ 0: retorna
  - Para cada recurso: calcula ganho respeitando capacidade
  - `vila.recursos_atualizados_em = dataAlvo`

**AplicadorOrdens** (`@Service`, `@Transactional`):
- `aplicar(ordem: Ordem, vila: Vila): void` — por categoria:
  - CONSTRUCAO: sobe `predio.nivel` para `ordem.nivel`; se é FAZENDA, cria novo Canteiro com TRIGO
  - FORJA: cria `ordem.quantidade` items com modelo/nível, origem FORJA, status DISPONIVEL
  - TREINO: cria unidade com tipo, arma (marca EQUIPADO), armadura (marca EQUIPADO), status DISPONIVEL

**EstadoVila** (record ou class de snapshot):
- Imutável, com todos os dados da vila, prédios, canteiros, sementes, itens, unidades, ordens para o mapper

**Testes** (`@DataJpaTest`, `@Import(VilaService)`, `RelogioAjustavel`, `AleatorioSequencia`):
- Criação: primeira chamada cria vila com estado inicial (nomes, prédios N1/0, recursos, 1 canteiro TRIGO, sementes 0)
- Idempotência: segunda chamada retorna mesma vila
- Produção após 2h sem requisições: serraria N1 (30/h) → +60 madeira
- Conclusão de ordens: ordem com `concluiEm` no passado é aplicada na sincronização
- Ordem em trechos: upgrade durante intervalo muda taxa no meio
- Lock pessimista: transação usa `FOR UPDATE`

## Critérios de aceite
- Vila criada com estado inicial exato (A.4)
- Produção calcula taxa × velocidade × tempo/3600 (floor, milésimos)
- Recursos respeitam capacidade (não ultrapassam)
- Ordens vencidas aplicadas em ordem cronológica
- Efeitos aplicados (nível sobe, canteiro novo, itens criados, unidades criadas)
- `sincronizar` chamado automaticamente em `obterParaAtualizacao`
- Lock pessimista impedindo race conditions
- Testes com `RelogioAjustavel` e `AleatorioSequencia` funcionam
