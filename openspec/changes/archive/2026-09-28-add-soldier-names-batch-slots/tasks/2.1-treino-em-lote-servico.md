## Notas de implementação

**QuartelService.treinar(Long usuarioId, TipoTropa tipo, int armaNivel, ModeloItem armaduraModelo, int armaduraNivel, int quantidade):**

1. **Validações iniciais:**
   - `quantidade` ∈ [1, 15] é validada por Bean Validation no `TreinarRequest` (`@Min(1) @Max(15)`), com resposta 400 `REQUISICAO_INVALIDA` antes de chegar ao serviço; o serviço não cria código novo
   - Busca vila do usuário; valida nível do quartel ≥ tipo.nivelQuartelMinimo; se não, retornar erro 422 `REQUISITO_NAO_ATENDIDO`
   - Valida que há apenas 1 ordem TREINO em andamento por vila (fila com 1 ordem)

2. **Cálculo de capacidade livre:**
   - `capacidadeLivre = 3 × nivelQuartel − unidadesVivas − somaQuantidadeOrdensEmAndamento`
   - Se `quantidade > capacidadeLivre` → erro 422 `CAPACIDADE_EXERCITO`, nada muda

3. **Validação de itens (armas):**
   - Busca armas do `tipo.modeloArmaExigido` e nível `armaNivel`, status `DISPONIVEL`, ordena por id
   - Se quantidade de armas disponíveis < `quantidade` → erro 422 `ITEM_INDISPONIVEL`, nada muda

4. **Validação de itens (armaduras):**
   - Busca armaduras do modelo `armaduraModelo` e nível `armaduraNivel`, status `DISPONIVEL`, ordena por id
   - Se quantidade < `quantidade` → erro 422 `ITEM_INDISPONIVEL`, nada muda

5. **Validação de comida:**
   - Calcula comida necessária: `comidaNecessaria = tipo.comidaPorTreino × quantidade`
   - Se vila.comida < `comidaNecessaria` → erro 422 `RECURSOS_INSUFICIENTES`, nada mada

6. **Transação — Reserva:**
   - Debita comida: `vila.comida -= comidaNecessaria`
   - Escolhe primeira N armas (menores ids), marca status `RESERVADO`, vincula a uma `Ordem` TREINO nova (ainda sem salvar)
   - Escolhe primeira N armaduras, marca status `RESERVADO`, vincula mesma ordem
   - Cria `Ordem` TREINO: `categoria=TREINO`, `alvo=tipo`, `nivel=armaNivel`, `quantidade=quantidade`, `iniciadaEm=agora`, `concluiEm=agora + ceil(tempo_tipo × quantidade / velocidade)`

7. **Retorna** a `Ordem` criada

**AplicadorOrdens.aplicarTreino(Ordem ordem, AplicadorOrdens aplicador):**

1. Busca todos itens onde `ordem_id = ordem.id`
2. Separa por categoria (`CategoriaItem`)
3. Ordena cada grupo por id
4. Forma pares: `for (i = 0; i < N; i++)` cria unidade com arma[i] + armadura[i]
5. Para cada par:
   - Cria `Unidade`: tipo = ordem.alvo, sorteio independente de nome e sobrenome: `var n = geradorNomes.sortear(); unidade.setNome(n.nome()); unidade.setSobrenome(n.sobrenome()); unidade.setOrdinalNome(1)` (provisório; a numeração real é da task 2.5 — manter a criação sequencial na ordem dos pares, arma de menor id primeiro)
   - Seta armaItemId = arma.id, armaduraItemId = armadura.id
   - Seta atributos iniciais (HP, ataque, defesa, movimento derivam do tipo e itens)
   - Marca arma e armadura com status `EQUIPADO` e **`ordemId = null`** (desvincula da ordem)
   - Salva unidade
6. Apaga `Ordem` (cascade delete para itens se houver, mas aqui itens estão desvinculados)

**Tratamento de erros:**
- Lançar `RegraJogoException` com `CodigoErro` existente (não inventar novos):
  - `CodigoErro.CAPACIDADE_EXERCITO` para capacidade excedida
  - `CodigoErro.ITEM_INDISPONIVEL` para itens insuficientes
  - `CodigoErro.RECURSOS_INSUFICIENTES` para comida insuficiente
  - `CodigoErro.REQUISITO_NAO_ATENDIDO` para nível de quartel insuficiente
  - Validação de quantidade fora de [1, 15] → 400 `REQUISICAO_INVALIDA` via Bean Validation (não trata no serviço)

## Critérios de aceite

- `TreinarRequest` novo com validações `@Min(1) @Max(15)` para quantidade, retorna 400 `REQUISICAO_INVALIDA` se fora do intervalo
- `AcoesVilaController.treinar` atualizado para passar novos campos (`armaNivel`, `armaduraModelo`, `armaduraNivel`, `quantidade`) para `QuartelService.treinar`

- Quantidade 0 ou 16 → 400 `REQUISICAO_INVALIDA` via Bean Validation
- Ordens são criadas com `quantidade`, itens reservados vinculados
- `AplicadorOrdens.aplicarTreino` forma pares arma+armadura, cria unidades com nomes
- Cada unidade do lote tem seu próprio sorteio de nome e sobrenome (duplicatas permitidas entre unidades do mesmo lote)
- Erros retornam 422 com código apropriado; nada muda no banco
- Testes cobrem: lote válido, quantidade excedida, itens insuficientes, comida insuficiente, capacidade excedida
