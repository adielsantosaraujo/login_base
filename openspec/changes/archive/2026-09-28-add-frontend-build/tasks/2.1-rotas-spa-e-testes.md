# Task 2.1 — Rotas da SPA, /app/** público e testes

**Índice:** [tasks.md](../tasks.md) · **Depende de:** — · **Paralela com:** 1.1, 1.2, 1.3

## Objetivo

Configurar o backend Spring Boot para servir a SPA em `/` e suas rotas (fallback de history mode), permitir acesso público aos assets em `/app/**`, e ajustar os testes para validar essas rotas sem depender do build do frontend.

## Contexto necessário

- [design.md — Decisão 6: `PaginaController`: lista explícita de rotas em vez de catch-all](../design.md#6-paginacontroller-lista-explícita-de-rotas-em-vez-de-catch-all) — evita conflitos
  > `@GetMapping({"/", "/fazenda", "/forja", "/quartel", "/masmorras", "/batalhas/{id}"})` mapeado para `sistema/seguro/index`, fallback do history mode. Lista explícita evita conflitar com `/api/**`, `/login` e erros 404 reais.

- [design.md — Decisão 7: `SecurityConfig`: `/app/**` em permitAll](../design.md#7-securityconfig-appp-em-permitall) — assets públicos
  > Adicionar `/app/**` ao permitAll (sem autenticação necessária). Assets são públicos, sem dados sensíveis.

- [design.md — Decisão 9: Testes sem depender do build](../design.md#9-testes-sem-depender-do-build) — testes independentes de artefatos
  > Criar um template mínimo só de teste em `src/test/resources/templates/sistema/seguro/index.html`. Testes rodam sem o build estar executado.

- [spec user-authentication — Requirement: Página inicial segura](../specs/user-authentication/spec.md#requirement-página-inicial-segura) — `/` autenticado → SPA; anônimo → /login
  > A aplicação SHALL servir em `GET /` a página da SPA, acessível apenas a usuários autenticados. Scenarios: usuário autenticado vê status 200; visitante anônimo redireciona para /login.

- [spec frontend-app — Requirement: Rotas da SPA servidas pelo backend](../specs/frontend-app/spec.md#requirement-rotas-da-spa-servidas-pelo-backend) — recarregar rota interna sem perder contexto
  > Backend responde às rotas do history `/`, `/fazenda`, `/forja`, `/quartel`, `/masmorras`, `/batalhas/{id}` com a view da SPA para usuários autenticados. Scenarios: `GET /fazenda` autenticado → 200 + view; `GET /forja` anônimo → redirect /login.

- [spec frontend-app — Requirement: Assets do frontend públicos](../specs/frontend-app/spec.md#requirement-assets-do-frontend-públicos) — `/app/**` sem auth
  > Recursos em `/app/**` acessíveis sem autenticação. Scenario: `GET /app/assets/<arquivo>` anônimo não redireciona para /login.

## Notas de implementação

**PaginaController:**

Substitua a configuração anterior por:

```java
@RestController
public class PaginaController {

    @GetMapping({"/", "/fazenda", "/forja", "/quartel", "/masmorras", "/batalhas/{id}"})
    public String index() {
        return "sistema/seguro/index";  // view resolvida por Spring View Resolver (Thymeleaf)
    }
}
```

Alternativa com `@Controller` e `ModelAndView` se preferir:

```java
@Controller
public class PaginaController {

    @GetMapping({"/", "/fazenda", "/forja", "/quartel", "/masmorras", "/batalhas/{id}"})
    public ModelAndView index() {
        return new ModelAndView("sistema/seguro/index");
    }
}
```

**SecurityConfig:**

No método `securityFilterChain` (ou equivalente), adicionar `/app/**` ao permitAll:

```java
.authorizeHttpRequests(authz -> authz
    .requestMatchers("/login", "/login/**", "/app/**").permitAll()  // adicionar "/app/**"
    .anyRequest().authenticated()
)
```

Ou, se usar pattern `/app/**` em outro lugar da config:

```java
authorizeRequests()
    .antMatchers("/login", "/login/**", "/app/**").permitAll()
    .anyRequest().authenticated()
```

   - Mudar assertion de conteúdo para `view().name("sistema/seguro/index")`

2. Adicionar novo teste: `usuarioAutenticadoAcessaRotaInterna_fazenda`
   ```java
   @Test
   @WithMockUser(username = "user1")
   void usuarioAutenticadoAcessaRotaInterna_fazenda() throws Exception {
       mockMvc.perform(get("/fazenda"))
           .andExpect(status().isOk())
           .andExpect(view().name("sistema/seguro/index"));
   }
   ```

3. Adicionar novo teste: `visitanteAnonimo_acessaRotaInterna_redireciona`
   ```java
   @Test
   void visitanteAnonimoAcessaRotaInterna_redireciona() throws Exception {
       mockMvc.perform(get("/forja"))
           .andExpect(status().is3xxRedirection())
           .andExpect(redirectedUrl("http://localhost/login"));
   }
   ```

4. Adicionar novo teste: `visitanteAnonimo_requisitaAsset_naoRedireciona`
   ```java
   @Test
   void visitanteAnonimoRequisitaAsset_naoRedireciona() throws Exception {
       // GET /app/assets/qualquer.js deve retornar 404 (não existe), não 302 (redirect)
       mockMvc.perform(get("/app/assets/qualquer.js"))
           .andExpect(status().is(404));  // ou 403 se static resources handler bloqueia
   }
   ```

   *Nota: O status exato pode ser 404 (recurso não existe) ou outra resposta, o importante é NÃO SER 302/redirect para /login.*

## Critérios de aceite

- PaginaController mapeia `/`, `/fazenda`, `/forja`, `/quartel`, `/masmorras`, `/batalhas/{id}` e retorna view `sistema/seguro/index`
- SecurityConfig permite acesso a `/app/**` sem autenticação (permitAll)
- Testes passam sem depender do build (template em src/test/resources)
- Teste: usuário autenticado acessa `/` → status 200 + view correta
- Teste: usuário autenticado acessa `/fazenda` → status 200 + view correta
- Teste: visitante anônimo acessa `/forja` → redirect para `/login`
- Teste: visitante anônimo requisita `/app/assets/x` → status 404/403, NÃO 302
