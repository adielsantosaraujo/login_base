# Task 1.2 — Curva de níveis e expoente configurável

**Índice:** [tasks.md](../tasks.md) · **Depende de:** — · **Paralela com:** [1.1](1.1-migracao-v5-niveis.md)

## Objetivo
Criar o objeto de valor `CurvaNiveis` (cálculo determinístico de `(N/5)^p` em BigDecimal) e a
propriedade `app.jogo.expoente-curva` em `JogoProperties`, validada na inicialização (faixa 1,0–2,0,
múltiplo de 0,25).

## Contexto necessário
- [design.md — D1 — Curva de níveis como objeto de valor em JogoProperties](../design.md#d1--curva-de-níveis-como-objeto-de-valor-em-jogoproperties) — onde a curva mora e como é obtida
  > Record puro `CurvaNiveis(BigDecimal expoente)` em `jogo/catalogo`, exposto por `JogoProperties.curvaNiveis()` (sem prefixo `get`); `CurvaNiveis.PADRAO` (p = 1,5) só para testes.
- [design.md — D2 — Potência determinística com expoente múltiplo de 0,25](../design.md#d2--potência-determinística-com-expoente-múltiplo-de-025) — algoritmo
  > `x = N/5`; `q = p×4`; `k = q/4`; `f = q%4`; `r = x^k`; `s = sqrt(x, DECIMAL128)`; `t = sqrt(s, DECIMAL128)`; se `f ≥ 2` → `r×s`; se `f` ímpar → `r×t` (multiplicações com DECIMAL128).
- [design.md — D3 — Validação do expoente na inicialização](../design.md#d3--validação-do-expoente-na-inicialização) — anotações
  > `@NotNull @DecimalMin("1.0") @DecimalMax("2.0") BigDecimal expoenteCurva = new BigDecimal("1.5")` + `@AssertTrue isCurvaNiveisValida()`.
- [spec game-village — Requirement: Expoente da curva de níveis configurável](../specs/game-village/spec.md#requirement-expoente-da-curva-de-níveis-configurável)
  > Padrão 1,5; 2,0 aceito; 2,5 ou 0,5 falham na inicialização; 1,3 falha (não é múltiplo de 0,25).
- [design.md — Tabela de valores de referência](../design.md#tabela-de-valores-de-referência) — valores esperados de `fator`
- [JogoProperties.java](/src/main/java/com/example/loginbase/jogo/config/JogoProperties.java) — estilo (`@Validated`, Lombok `@Getter/@Setter`)
- [JogoPropertiesTest.java](/src/test/java/com/example/loginbase/jogo/JogoPropertiesTest.java) — padrão `ApplicationContextRunner` + `hasFailed()`

## Notas de implementação
- `CurvaNiveis`: constantes `NIVEL_BASE = 5`, `EXPOENTE_PADRAO = new BigDecimal("1.5")`, `EXPOENTE_MINIMO = 1.0`, `EXPOENTE_MAXIMO = 2.0`, `PADRAO = new CurvaNiveis(EXPOENTE_PADRAO)`. Construtor compacto: `Objects.requireNonNull`; fora de [1,0; 2,0] ou `expoente × 4` não inteiro → `IllegalArgumentException` com mensagem clara.
- `public BigDecimal fator(int nivel)`: `nivel ≥ 1` (senão `IllegalArgumentException`); `x = BigDecimal.valueOf(nivel).divide(BigDecimal.valueOf(5))` (divisão exata); algoritmo de D2 com `MathContext.DECIMAL128`. Não usar `double`/`Math.pow`.
- Nesta task **não** criar `verificarLimites()` (depende das fórmulas da task 2.1). `isCurvaNiveisValida()` aqui só tenta `new CurvaNiveis(expoenteCurva)` e devolve `false` em exceção. Documentar no Javadoc que a task 2.1 acrescentará a verificação de overflow.
- `public CurvaNiveis curvaNiveis()` em `JogoProperties` (sem `get`, para o binder não tratar como propriedade).
- `CurvaNiveisTest` (valores de referência exatos, comparar com `compareTo`/`isEqualByComparingTo`):
  - p = 1,5: `fator(20)` = 8; `fator(5)` = 1; `fator(10)` = `2.828427124746190097603377448419396`; `fator(6)` = `1.314534138012398672296727478721925`; `fator(100)` = `89.44271909999158785636694674925104`.
  - p = 1,25: `fator(80)` = 32; p = 1,75: `fator(80)` = 128; p = 2,0: `fator(10)` = 4; p = 1,0: `fator(10)` = 2.
  - Construtor rejeita `null`, 0.99, 2.01, 2.25, 1.3, 1.1.
- `JogoPropertiesTest` (novos): padrão 1,5; `app.jogo.expoente-curva=2.0` e `=1.25` aceitos; `=2.5`, `=0.5`, `=1.3` → `hasFailed()`.

## Critérios de aceite
- `CurvaNiveis` pura (sem Spring), determinística, com os valores exatos acima.
- A aplicação não inicia com expoente inválido; com padrão ou valores válidos inicia.
- `.env.example`, `docker-compose.yml` e `application.properties` expõem a variável.
