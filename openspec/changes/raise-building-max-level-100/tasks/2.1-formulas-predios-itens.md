# Task 2.1 — Fórmulas de prédios e itens com a curva

**Índice:** [tasks.md](../tasks.md) · **Depende de:** [1.1](1.1-migracao-v5-niveis.md), [1.2](1.2-curva-niveis-expoente.md) · **Paralela com:** —

## Objetivo
Implementar no catálogo as fórmulas em duas faixas (custo, tempo, capacidade do armazém, canteiros,
nível forjável), subir o nível máximo de item para 23 preservando o loot ≤ 5, ligar a `CurvaNiveis` a
todos os chamadores e acrescentar a verificação de overflow na inicialização. Resolve o
`ArithmeticException: Overflow` de `GET /api/jogo/catalogo`.

## Notas de implementação
- `Custo.paraNivel(int nivel, CurvaNiveis curva)`: N ≤ 5 igual a hoje (`1.5^(N−1)` exato); N > 5 `base × FATOR_NIVEL_5 (5.0625) × curva.fator(N)` → `setScale(0, HALF_UP).longValueExact()`.
- `TipoPredio`: manter `NIVEL_MAXIMO = 100` (já editado localmente); Javadoc da classe com níveis 0–100 e as fórmulas em duas faixas; `custo(int, CurvaNiveis)`; `tempoSegundos(int)` com D4; `capacidadeRecurso(int, CurvaNiveis)`; `numeroCanteiros(N)` = `N ≤ 5 ? N : 5 + (N − 5) / 5`; `NUMERO_MAXIMO_CANTEIROS = 24`; `nivelMaximoForjavel(N)` = `N ≤ 10 ? N : N ≤ 50 ? 10 + (N − 10) / 5 : 18 + (N − 50) / 10`. Produção e `capacidadeExercito` inalteradas.
- `TipoRecurso.capacidadeArmazem(int nivel, CurvaNiveis curva)`: validar `1..TipoPredio.NIVEL_MAXIMO` (sem literal 100); N ≤ 5 `500L << (N−1)`; N > 5 `round_half_up(8000 × fator)`.
- `ModeloItem.NIVEL_MAXIMO = 23`; Javadoc "nível L 1 a 23". Fórmulas de atributos/custo/tempo inalteradas.
- `GeradorLoot`: `private static final int NIVEL_MAXIMO_ITEM_LOOT = 5;` e `Math.min(NIVEL_MAXIMO_ITEM_LOOT, nivelMasmorra + aleatorio.proximoInt(2))`; Javadoc explicando o desacoplamento de `ModeloItem.NIVEL_MAXIMO`.
- `CurvaNiveis.verificarLimites()`: para cada `TipoPredio` e N em 1..100, `tipo.custo(N, this)`; para N em 1..100, `Math.multiplyExact(TipoRecurso.capacidadeArmazem(N, this), 1000L)`. `JogoProperties.isCurvaNiveisValida()` passa a chamar `verificarLimites()` após construir a curva (qualquer `RuntimeException` → `false`).
- Chamadores: `VilaService` → `new CalculadoraProducao(jogoProperties.getVelocidade(), jogoProperties.curvaNiveis())`; `CalculadoraProducao.capacidadeMaxima(n)` = `Math.multiplyExact(TipoRecurso.capacidadeArmazem(n, curva), 1000L)`; `JogoMapper` usa `jogoProperties.curvaNiveis()` em `new CalculadoraProducao(...)`, `capacidadeArmazem(...)`, `tipo.custo(...)` (em `toPredioDto` e `toCatalogoDto` — este recebe `JogoProperties` por parâmetro); `ConstrucaoService` → `tipo.custo(nivelAlvo, jogoProperties.curvaNiveis())`; `MasmorraService` ganha `JogoProperties` no construtor e usa `capacidadeArmazem(nivelArmazem, jogoProperties.curvaNiveis())` em `aplicarLoot`.

  - `CurvaNiveisTest`: `verificarLimites()` não lança para 1,0 / 1,5 / 2,0.

## Critérios de aceite
- `GET /api/jogo/catalogo` não lança overflow e traz 100 níveis por prédio.
- Níveis 1–5 idênticos aos atuais em custo, tempo e capacidade; valores acima de 5 conforme a tabela de referência.
- Loot da masmorra continua com itens ≤ 5; forja/treino aceitam nível 1–23 na validação de request.
- Aplicação não inicia se `verificarLimites()` falhar.
- Compila sem as versões de um argumento de `custo`/`capacidadeArmazem`/`capacidadeRecurso`/`paraNivel`.
