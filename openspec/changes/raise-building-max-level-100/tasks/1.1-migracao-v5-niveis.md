# Task 1.1 — Migração V5 e reversão do V3

**Índice:** [tasks.md](../tasks.md) · **Depende de:** — · **Paralela com:** [1.2](1.2-curva-niveis-expoente.md)

## Objetivo
Desfazer a edição local não commitada em `V3__jogo.sql` e criar a migração `V5__niveis_estendidos.sql`
que amplia as constraints de nível de prédio (0–100), posição de canteiro (1–24) e nível de item (1–23),
com testes de repositório cobrindo as novas faixas.

## Contexto necessário
- [design.md — D9 — Migração V5 e reversão do V3](../design.md#d9--migração-v5-e-reversão-do-v3) — SQL exato e motivo de não usar repair
  > `alter table jogo_predios drop constraint ck_jogo_predios_nivel;` … `check (nivel between 0 and 100)`;
  > `ck_jogo_canteiros_posicao` → `posicao between 1 and 24`; `ck_jogo_itens_nivel` → `nivel between 1 and 23`.
- [design.md — Migration Plan](../design.md#migration-plan) — nota operacional do banco de desenvolvimento
  > Não rodar `flyway repair`; se o Flyway acusar checksum divergente do V3, parar e avisar o orquestrador (o usuário limpa o banco).
- [spec game-data — Requirement: Integridade dos níveis e quantidades](../specs/game-data/spec.md#requirement-integridade-dos-níveis-e-quantidades) — faixas novas
  > Prédios 0–100, canteiros 1–24, sementes ≥ 0, itens 1–23. Cenários: prédio 101 rejeitado; prédio 100 aceito; item 23 aceito; item 24 rejeitado; canteiro 25 rejeitado.
- [spec game-data — Requirement: Migração V5 para níveis estendidos](../specs/game-data/spec.md#requirement-migração-v5-para-níveis-estendidos) — V1–V4 não podem ser editadas
- [V3__jogo.sql](/src/main/resources/db/migration/V3__jogo.sql) — hoje com `nivel between 0 and 100` (edição local); deve voltar a `0 and 5`
- [V4__unidade_nome_e_lote_treino.sql](/src/main/resources/db/migration/V4__unidade_nome_e_lote_treino.sql) — estilo de comentário de migração
- [RepositoriosJogoTest.java](/src/test/java/com/example/loginbase/jogo/dominio/RepositoriosJogoTest.java) — padrão `saveAndFlush` + `DataIntegrityViolationException` (ex.: `deveRespeitarUniqueConstraintDePredioPorVilaETipo`)

- Novos testes em `RepositoriosJogoTest` (nomes sugeridos): `deveAceitarPredioNoNivelCem`, `deveRejeitarPredioNoNivelCentoEUm`, `deveAceitarCanteiroNaPosicaoVinteEQuatro`, `deveRejeitarCanteiroNaPosicaoVinteECinco`, `deveAceitarItemNoNivelVinteETres`, `deveRejeitarItemNoNivelVinteEQuatro`. Rejeição = `DataIntegrityViolationException` no `saveAndFlush`.
- Não alterar código Java de produção nesta task (as edições locais em `TipoPredio`/`TipoRecurso` ficam para a task 2.1).
