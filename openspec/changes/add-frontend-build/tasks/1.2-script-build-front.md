## Objetivo

Criar o script Python `scripts/build_front.py` que executa o build do frontend via Docker Compose, valida a geração do `dist`, copia os assets para o backend e registra o log, seguindo o estilo dos scripts existentes (`executar.py`, `cores.py`).

## Contexto necessário

- [design.md — Decisão 1: Script Python `scripts/build_front.py` no estilo de `executar.py`](../design.md#1-script-python-scriptsbuild_frontpy-no-estilo-de-executarpy) — padroniza com scripts existentes
  > Criar um script Python dedicado que executa o build via `docker compose run --rm --build frontend-build`, valida que `frontend/dist/index.html` foi gerado, copia os assets e registra log em `build.log`. Funções: `log`, `run`, `gerar_dist`, `copiar_dist`, `main`.

- [design.md — Decisão 2: Build via `docker compose run --rm --build` em vez de `up`](../design.md#2-build-via-docker-compose-run---rm---build-em-vez-de-up) — garante rebuild limpo e propagação correta do exit code
  > `run --rm` resgata `node_modules` novo da imagem recém-buildada e propaga corretamente o exit code do npm build. Com `up`, um build com erro sairia com status 0.

- [design.md — Decisão 4: Destinos: assets em `/app/` e template em templates/](../design.md#4-destinos-assets-em-appp-e-template-em-templates) — define destinos e estrutura
  > Assets em `src/main/resources/static/app/`; `index.html` em `src/main/resources/templates/sistema/seguro/index.html`.

- [spec frontend-app — Requirement: Build de produção integrado ao backend](../specs/frontend-app/spec.md#requirement-build-de-produção-integrado-ao-backend) — scenario "Build bem-sucedido" e "Build com erro"

- [scripts/executar.py](/scripts/executar.py) — modelo de estilo e estrutura

**Comportamentos esperados:**

1. **Build bem-sucedido:**
   - Limpar `build.log` anterior (truncar)
   - Executar `docker compose run --rm --build frontend-build`
   - Validar que `frontend/dist/index.html` existe (tamanho > 0)
   - Remover `src/main/resources/static/app/` inteiro (se existir)
   - Copiar `frontend/dist/*` (exceto `index.html`) para `static/app/`
   - Copiar `frontend/dist/index.html` para `templates/sistema/seguro/index.html`
   - Gravar log: "Build concluído com sucesso" ou similar
   - Retornar exit code 0

2. **Build com erro:**
   - Se `docker compose run ...` retornar código != 0, NÃO copiar nada
   - Gravar log do erro
   - Retornar o código de erro (propagação)
   - `static/app/` fica intacto (reutiliza versão anterior se existir, senão fica vazio)

3. **Log:**
   - Cada ação log: timestamp, cor, mensagem
   - Gravar em `build.log` na raiz (append ou truncar a cada execução, conforme spec)
   - Spec diz "truncado a cada execução" → limpar antes de começar

## Critérios de aceite

- Script é executável e sem syntax errors (`python3 -m py_compile scripts/build_front.py`)
- Estrutura segue padrão de `executar.py` (shebang, encoding, imports, funções, main)
- Função `gerar_dist()` chama `docker compose run --rm --build frontend-build` com tratamento de erro
- Função `copiar_dist()` copia corretamente e não causa estado inconsistente em erro
- Build com sucesso: `static/app/` atualizado, template novo, log gerado, exit 0
- Build com erro: nada copiado, log do erro, exit != 0
