# Task 1.1 — Serviço frontend-build e base do Vite

**Índice:** [tasks.md](../tasks.md) · **Depende de:** — · **Paralela com:** 1.2, 1.3, 2.1

## Objetivo

Criar o serviço Docker `frontend-build` no `docker-compose.yml` com profile `build` e configurar a base URL do Vite para `/app/` apenas na produção, possibilitando que o backend sirva corretamente os assets gerados.

## Contexto necessário

- [design.md — Decisão 3: Serviço dedicado `frontend-build` com profile `build`](../design.md#3-serviço-dedicado-frontend-build-com-profile-build) — evita interferência no volume de desenvolvimento
  > Criar um serviço separado no `docker-compose.yml` com profile `build` em vez de reutilizar o serviço `frontend` existente. Não interfere no volume nomeado `frontend-node_modules` do dev. Volume anônimo `/app/node_modules` do build é descartado no `--rm`.

- [design.md — Decisão 5: Vite: `base: '/app/'` apenas no build](../design.md#5-vite-base-appp-apenas-no-build) — dev server continua em `/`
  > `frontend/vite.config.ts`: `defineConfig(({ command }) => ({ base: command === 'build' ? '/app/' : '/', ... }))`. Dev funciona na raiz. Produção referencia assets em `/app/**`.

- [spec frontend-app — Requirement: Build de produção integrado ao backend](../specs/frontend-app/spec.md#requirement-build-de-produção-integrado-ao-backend) — define o que o build deve entregar

- [docker-compose.yml](/docker-compose.yml) — adicionar serviço `frontend-build`

- [frontend/vite.config.ts](/frontend/vite.config.ts) — definir `base` condicional

## Notas de implementação

**docker-compose.yml:**
- Adicionar serviço `frontend-build` após o `frontend` existente
- `image: node:20-alpine` (mesma da imagem base do frontend, ou usar Dockerfile customizado se necessário)
- `working_dir: /app`
- Volumes: `./frontend:/app` e `node_modules:/app/node_modules` (anônimo, descartado com `--rm`)
- `command: npm run build` (assume que existe em frontend/package.json)
- `profiles: ['build']` (não sobe automaticamente em `make up`)
- Sem `ports` nem `environment` especiais (herda do `.env` se necessário)

**frontend/vite.config.ts:**
- Padrão esperado: usar `defineConfig` com uma função que recebe `{ command, mode }` como parâmetro
- Adicionar `base` na configuração retornada: `base: command === 'build' ? '/app/' : '/'`
- Manter proxy/watch do dev server existentes
- Exemplo mínimo:
  ```typescript
  import { defineConfig } from 'vite'
  import vue from '@vitejs/plugin-vue'

  export default defineConfig(({ command }) => ({
    base: command === 'build' ? '/app/' : '/',
    plugins: [vue()],
    server: {
      proxy: { ... }  // manter existente
    },
    build: { ... }  // manter existente
  }))
  ```

## Critérios de aceite

- Serviço `frontend-build` existe no `docker-compose.yml` com profile `build` e roda sem erro quando chamado com `docker compose run --rm --build frontend-build`
- Vite config define `base: '/app/'` apenas em modo `build` (dev continua em `/`)
- `docker compose config --profiles` lista `build`
- `frontend/dist/index.html` gerado contém referências corretas a `/app/assets/...`

## Verificação

```bash
# Confirmar que o serviço existe e está com o profile correto
docker compose config --profiles | grep -i build

# Listar serviços no profile build
docker compose --profile build config --services | grep frontend-build

# Tentar buildar o serviço (deve funcionar ou erro do Vite/npm, não do Docker)
docker compose run --rm --build frontend-build

# Verificar que index.html foi gerado
test -f frontend/dist/index.html && echo "✓ index.html exists"

# Confirmar que references em index.html apontam para /app/assets/
grep -q '/app/assets/' frontend/dist/index.html && echo "✓ base path correct"
```
