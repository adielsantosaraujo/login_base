## Notas de implementação
- V18 = DDL do design D5 **sem** as linhas `drop table regiao_bonus;` e `drop table ladrilho_jazida;`; deixar no topo o comentário `-- (task 6.1 acrescenta aqui: drop table regiao_bonus; drop table ladrilho_jazida;)`.
- `RegiaoTerreno`: `@Entity @Table(name = "regiao_terreno")`, `Long id` identity, `long regiaoId` (`regiao_id`, não atualizável), `TipoTerreno terreno` (`@Enumerated(EnumType.STRING)`, length 20), `int posicao`, `int percentual` (ambos `@JdbcTypeCode(SqlTypes.SMALLINT)`); construtor `(long regiaoId, TipoTerreno terreno, int posicao, int percentual)`.
- `Ladrilho`: `@Entity @Table(name = "ladrilho")`, `Long id` identity, `long regiaoId`, `int x`, `int y`, `TipoTerreno terreno`, `int bonusBase` (`bonus_base`), `int bonusAdjacente` (`bonus_adjacente`) — x, y e bônus com `@JdbcTypeCode(SqlTypes.SMALLINT)`; método `public int getBonusTotal()` = base + adjacente (não mapeado; se o Lombok/Hibernate tentar mapear, anotar `@Transient`); construtor `(long regiaoId, int x, int y, TipoTerreno terreno, int bonusBase, int bonusAdjacente)`.
- Repositórios com os métodos exatos do design D5: `findByRegiaoIdOrderByPosicao`, `findByRegiaoIdIn` (terrenos); `findByRegiaoIdOrderByYAscXAsc`, `findByRegiaoIdAndXAndY`, `findByRegiaoIdAndTerrenoOrderByYAscXAsc`, `existsByRegiaoId` (ladrilhos).
- Testes novos em `ModeloJogoBaseIntegrationTest` (criar vila + região como os testes existentes): grava e lê 3 `RegiaoTerreno` em ordem de posição; grava ladrilhos e confere `getBonusTotal()`; `findByRegiaoIdAndXAndY`; `findByRegiaoIdAndTerrenoOrderByYAscXAsc` em ordem de varredura; CHECKs rejeitam (posição 1 com 61, posição 3 com 9, `bonus_adjacente` 30, `bonus_base` 101, x = 10, terreno inválido via SQL nativo) e o único `(regiao_id, x, y)` rejeita duplicata. Não remover os testes existentes de `LadrilhoJazida`/`RegiaoBonus` (task 6.1).
